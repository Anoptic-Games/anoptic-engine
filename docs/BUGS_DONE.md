## Removed guards

A second census, taken 2026-07-25 and running the other way. The buckets above ask what defect is missing a check; this section records checks that were deleted for costing without paying.

A guard qualified as frivolous on two conditions together: it rejects inputs that cannot arise under reasonable use of its API, and the effect it prevents is contained 〜 the call merely fails, returns early, or yields a wrong-but-bounded value, with no out-of-bounds access, no UB, no leak, no corruption of unrelated state. Either condition alone acquits. A guard against an absurd input whose effect is a heap overwrite stays, however unreachable the input; a guard on a reachable input stays whatever its effect. Severity scaled with how hot the branch was.

The sweep read roughly 1,650 guard sites across all sixteen modules, one reader per module. Eleven modules came back clean. Thirteen findings in five, plus the `ano_sleep` guard removed the same day and recorded as a `wontfix` above. Every removal below is in the tree; the suite was run after and showed the same five pre-existing failures as before, all of them open decisions at the time and all since settled 〜 see "Settled open decisions" below.

### Why these existed

Four shapes account for all thirteen.

Arithmetic artifacts. Someone traced a wrap or a sentinel and guarded the input that triggers it, without asking whether that input can occur or whether its effect matters. `ano_sleep` (~585 years), `audio_mixer.c:187` (~12.2 million years), `frame.h:94` (71.6 minutes). The tell is platform divergence: `time_linux.c` never carried the `ano_sleep` guard, because splitting `us` into `tv_sec`/`tv_nsec` never forms the product that wraps. A constraint that is real appears in every sibling, or in the header. None of these appear in either.

Invariant distrust. A counter's decrement is guarded against underflow while the matching increment in the same function is not. If the invariant holds neither test is needed; if it does not, the increment is equally wrong. The asymmetry is the argument.

Prototype transliteration. `max(1, ...)` carried across from the Python prototype, where slice semantics gave it meaning. In C it is inert.

Redundant re-checks of a callee's own bound, or of a bound the type already enforces.

### Removed

`src/audio/audio_mixer.c:187` 〜 `if (s->remaining != UINT64_MAX) s->remaining--;`. Guarded the play-until-STOP sentinel against being consumed, which takes 2^64 frames: ~12.2 million years at 48 kHz. Per-sample per-voice in `source_render`, ~3M evaluations/second at 64 voices. The decrement is now unconditional; an unbounded voice counts down from `UINT64_MAX` instead of sitting pinned at it, and the sole reader (`:117`, `remaining == 0 && state == PLAYING`) cannot observe the difference in any real runtime.

`src/audio/dsp/delay.h:54-55` 〜 `if (delay < 1u) delay = 1u; if (delay > d->cap) delay = d->cap;`. Dead at all four call sites, each of which reads a line with the value it was allocated with. The index is masked by `& d->mask` regardless, so a violating delay reads a different in-buffer slot rather than out of bounds. Twelve dead compares per sample on a bus running reverb. The doc comment promised the clamp and was corrected; the file header now says only the fractional read clamps. `ano_dsp_delay_read_frac`'s clamps at `:62-63` were left 〜 they stop a negative or huge float reaching `(uint32_t)delay`, which is UB, so they fail the containment condition.

`src/time/time_win64.c:251` 〜 `if (startTime == 0 || startTime == UINT64_MAX) return -1;` in `ano_busywait`. ## Remediation determinations

A third pass, 2026-07-25, over the notes above. Nine inspections, one agent per finding, each ordered to verify before proposing and then to pick the highest rung of a fix hierarchy that fully neutralizes the defect: structural (reordering makes the bad state unreachable, no added code), type (the bad value becomes unrepresentable), other compile-time (static_assert, signatures), runtime invariant (established once at a seam, inherited everywhere downstream), and guards at the fault site last. Nothing in this section was implemented when it was written; it records what should land and why, and the coda below records the landing. Of eleven determinations, five land at tier 1, six at tier 4, and zero at tier 5 〜 every check that must exist sits at a seam, none at a fault site. `music_motif.c:472` from the list above was not in scope and stays unverified.

`src/time/` (both notes) 〜 confirmed, tier 1. The sentinel arithmetic is exact: at 10 MHz a failed QPC read comes out of `ano_ticks_to_ns` as `UINT64_MAX - 99`, so every `== UINT64_MAX` check downstream misses the failure it names. Worse, all sentinel producers are unreachable: Microsoft documents QPC/QPF as unable to fail on XP+ (the file targets Win10 1803+ and its own comment at `:40` says so), `mach_absolute_time` is a commpage read, and vDSO `clock_gettime` with a valid constant clockid cannot fail. ## Settled open decisions (from docs/BUG-HUNT.md)

Moved out of "Open decisions" in `docs/BUG-HUNT.md`. Nothing stands there now: all five are settled and implemented.

### log_core.c:817 〜 size-mismatch (bucket 2, anotest_logflood)

The one entry quantity safety did not close, because it is not arithmetic. `g_batch` is sized at ring bytes plus 16 per record on the claim that a record's rendered text fits its ring footprint, but a deferred record renders at its format width, not its stored size, so `"%*d"` width 4000 holds one 64-byte ring line and emits ~4016 batch bytes.

Decide what the logger promises under a wide-format flood. Bounding rendered width at capture (reject or clamp a format whose width exceeds the record's share) keeps the drain's memory profile flat and changes what the public logger accepts. Sizing the batch by a rendered bound with checked per-record copies keeps the contract and lets the drain allocate against a hostile format string. The first is a contract change, the second is a memory-profile change; the checked `room` subtraction is required either way and is not by itself the fix.

Settled 2026-07-25 by a third answer neither horn anticipated: the contract stands 〜 full width, no drops 〜 and the memory profile stays flat; the drain flushes mid-pass whenever less than one worst-case rendered record of room remains, so a flood pays file writes, not memory and not contract. anotest_logflood is green and the census entry is closed. Details under "Remediation determinations".

### ano_render_bridge.c:92 and ano_audio.c:204 〜 ownership-leak (bucket 4, anotest_bridgeguard, anotest_audioshutguard)

One decision wearing two module names. Both destroy paths tear down a ring without discharging the payloads still inside it: the render bridge hands the commands ring to `ano_spsc_destroy`, which frees only `ring->buffer`, so every enqueued `bulk_owned` block loses its last reference; the audio world never walks `mx->buffers` or drains a ring, and adopted blocks live on the default mi heap rather than the module heap teardown frees.

Decide where the drain obligation lives. If it belongs to the ring, `ano_spsc_destroy` needs a per-element release callback and the transport becomes aware of payload ownership. If it belongs to the owner, each destroy walks its own ring before handing over the storage and the transport stays dumb. `docs/URGENT-audiorace.md` already commits to migrating audio, render and log onto one `anoring_spsc`, so whichever answer lands here becomes the shared contract for all three 〜 deciding it inside a single bug fix would prejudge that migration.

The audio side carries a second question the render side does not: `anoptic_audio.h:326` promises an adopted block rides home to its producer, and a producer cannot poll a destroyed world. Either destroy frees adopted blocks outright and the lossless-block invariant gains a documented exception at teardown, or shutdown becomes a two-phase drain the producer takes part in. The header has to change either way; which sentence changes is the decision.

Settled 2026-07-25 by the tier policy. The drain obligation belongs to the owner and the transport stays payload-agnostic: tier 1, because every other drop path already discharges through the owner's own free routines and destroy was the one asymmetric sibling, completed with the existing pop and discharge at one more call site; tier 2 rejects the ring callback as necessarily type-erased, moving payload knowledge away from the module that owns the type behind a runtime registration a caller can forget. That settles the `anoring_spsc` migration contract at its minimum 〜 transports move bytes, owners discharge payloads 〜 rather than prejudging it. The audio question fell with it: destroy frees adopted blocks outright and the rides-home promise carries a teardown clause, because the two-phase alternative keeps the lossless invariant total only by exporting a liveness obligation to a producer the module can neither discharge nor enforce 〜 an invariant homed outside the tree, below every tier. A loan cannot outlive the lender; the borrower's death discharges, it does not return.

### music_voicing.c:114 〜 shared-mutable-state (bucket 6, anotest_musicguard)

`ano_voice_chord` builds its candidate table in a 6 KiB function-scope static commented "single-threaded conductor context", while the module's own hosting design in `ANOPTIC_MUSICGEN.md` runs a second engine off-thread through the same call. TSan confirms the write-write race. 6 KiB is too large to move to the audio-thread stack, so the scratch has to live somewhere with an owner.

Decide the composer's ownership model. Engine-owned scratch means the engine struct gains a field and its init and teardown gain an obligation, and it stays correct if an engine ever migrates between threads. Thread-local scratch is a smaller diff and is wrong the moment one engine is driven from two threads across its life. The same rule decides `music_theory.c:48`'s lazy-bake static, currently a lead and benign on x86 only by luck 〜 settle both together, because "statics are fine here" is exactly the assumption that produced both.

Settled 2026-07-25 at the verify gate rather than by choice. Both candidate homes were tier 2, so the framing posed a decision the hierarchy does not rank; and the objection to thread-local rested on cross-call state the buffer does not have 〜 candCount resets to zero every call and bounds every read, proven read-site by read-site before the edit. thread_local landed as the zero-new-obligation shape. ### ano_strings_collate.c:75 〜 table-coverage-gap (bucket 5, anotest_strguard)

The CE and decomp tables are both generated by `tools/gen_unicode_tables.c` and disagree about coverage, so U+01EF and U+0374 have correct direct CE listings that are unreachable behind decomp redirects to code points the CE trim removed. Repairing the two named code points by hand leaves the generator free to reopen the hole somewhere else, which is why this is not an edit.

Decide the generator invariant: either the CE trim takes a closure over the decomposition graph (never drop an entry any kept decomposition targets), or the decomp trim drops any redirect whose target left the CE table. The first keeps more weight data and a larger table; the second is smaller and silently reroutes more code points to implicit weights. The same choice settles the `ano_unicode_tables.h` case-trim lead (`anorune_to_upper(0x0292)` versus `to_lower(0x01B7)`), which is the identical disease in the case-pair table 〜 fix them under one invariant or the next trim reopens both.

Settled 2026-07-25 by measurement. The policy fixed the home first: the invariant lives in the generator, welded by assert_trim_closure, which fails generation 〜 nonzero exit, no file written 〜 whenever a kept decomp redirect targets a CE-unlisted code point or a case mapping leaves the shipped table. The direction question then dissolved: the divergence set (code points holding a redirect into the hole and no direct CE listing of their own) measured empty, so the smaller closure landed and the two named code points reach the direct listings they always had. The same closure on the case-pair table swept 26 mappings whose partner had left the shipped set 〜 every one a broken round trip, to_lower handing back a code point the same table reports uncased and uncategorized 〜 which now return identity, making case mapping an involution on the shipped set. Direction A (widen the keep-list to swallow the 26 partners, preserving Unicode casing at the cost of pulling IPA Extensions and pieces of Latin Extended-C/D into a shipped-scripts table) remains a one-line flip to case_delta_kept plus a keep-list edit, and the weld holds either choice honest. The pass also surfaced the generator's padding-memcmp dedup (its own census entry) and left one lead: with the closure in place zero kept decompositions lack a direct CE listing, so the decomp table may be dead weight for collation as implemented.

Device and surface re-creation, if ever wanted, replaces this latch with a rebuild path 〜 the latch is the placeholder for that door, not a substitute for it.

ano_GltfParser.c, the bindless-full latch 〜 once bindless_register_texture has refused, should the parser keep decoding and uploading the rest of the asset? Ruled: no. The bindless array is monotonic and nothing releases a slot, so the first refusal proves every later registration in the process refuses, and each further decode burns CPU, staging and VRAM for a slot that can never be addressed. The latch is parse-local and derived from the registrar's published answer word, checked at the loop's existing pre-decode skip seam, with the refusing texture itself still fully processed and adopted and one summary warning after the loop. Reading the bindless array's own counters from the parser was forbidden: texture.c remains the sole decoder of fullness. The residual the ruling names itself 〜 one wasted decode per parseGltf call, because the latch is per-asset 〜 is the deliberate price of not exporting a fullness predicate through texture.h, and that export is still open under "Open design questions".

apply.c, the shared static light decode 〜 the static path built LightData field by field and dropped localDir; the runtime path built the same struct through light_data_from_params and honored it. Ruled: share the decode, with the zero offset pinned explicitly, and yes 〜 the caster geometry follows the photometrics, so a casting static UPDATE refreshes the influence volumes the row already owns, through a no-grant refresh homed in shadow_casters.c beside the grant and revoke halves. Documenting the drop instead was rejected as permanently amputating per-light aim for scene lights and making one public struct mean different things in two regions; adding localDir alone was rejected as leaving two decodes free to drift again on the next field. The consistency argument, not a reachability argument, is what settles it: a whole-row overwrite cannot have a decode that silently discards part of the row. The declaration's home is provisional 〜 it sits in light_registry.h because both natural homes were off-surface 〜 and backend.h:34-35 still under-describes its own path; both are ledgered under "Open design questions". Both were closed in round 6: the declaration moved to backend.h beside its siblings and the contract prose was amended in round 5.

bridge/apply.c, the rate bound on the static-UPDATE contract reports 〜 round 5 gave the static light lane two new diagnostics (a dropped castsShadow raise, a LightType the owned block does not hold), and a producer resending a bad whole-row payload every frame logs every frame. The question was whether those reports carry a per-row latch. Ruled: unbounded per offending command, as landed, on the module's own discipline 〜 gate_light_domain, the seam a round-3 ruling made the sole refusal channel on this lane, has exactly this shape and exactly this exposure, and matching it keeps one shape on one lane. A 64-bit per-row latch would make this the only rate-bounded diagnostic in the backend, needs its own state in RendererState and its own clear-on-re-create rule 〜 new invariants to guard, for a flood only a broken producer can cause 〜 and it hides a second occurrence after a correcting re-create. The campaign's refusals-budget shape was rejected for the same reason: it is a device-loop idiom, and this is a caller-error idiom. If diagnostic seams on hot lanes ever do take per-subject latches, the decision belongs to the lane, which means revisiting gate_light_domain, not this seam alone.

geometry.h, how the mesh pool spells refusal 〜 geometry_pool_upload answered 0 both for "pool full or transfer failed" and as the index of the first granted slot, and 0 is also FALLBACK_MESH_INDEX, the very word its caller compared against. The question was whether to reserve a sentinel, convert the face to the total-out-param shape, or fix only the caller. Ruled: reserve the sentinel, following the round-3 bindless precedent one file over for the byte-identical shape 〜 a refusal spelled as a valid grant. ANO_MESH_NONE is 0xFFFFFFFFu, welded by _Static_assert against ANO_MAX_MESHES so a grant can never spell it, and again at scene_buffers.c against NO_MESH_INDEX and ANO_RENDER_NO_MESH so the refusal is the same word both consuming lanes already read as absent. The weld is arithmetic, not asserted at a call site. The total-out-param conversion was rejected as rewriting every call site and the header signature for no gain the sentinel does not already give; fixing only the caller was rejected as detecting success by side effect and doing nothing for the other callers. The consequence the ruling wanted is that the caller's test can fire at all, after which the fallback-mesh arm takes the same unwind its texture twin already has.

include/anoptic_render.h, where castsShadow's static lane is documented 〜 round 5 made the static lane's one-directional behaviour audible at ANO_ERROR, and stated it in backend.h, which is a private backend header the producer never sees. The question was whether a public field's per-command asymmetry belongs in the public header. Ruled: yes, and in the voice the header already uses 〜 the sibling `type` field two lines up documents both lanes per-command, so the convention was already set and castsShadow was the field that did not follow it. A producer must not first learn the rule from a log line. The renderer-side text stays where it is: backend.h describes what the backend does, anoptic_render.h describes what the producer may ask for, and the two now agree.

### Platform verification posture

The campaign fixed four defects on platforms it could not execute, plus four Windows strays. They are recorded here as inspection-grade with their checklists, not as verified.

Darwin is the exception and was verified on-host. The barrier fix was built and run outside any build directory with the system toolchains: the cohort-accounting harness against HEAD's implementation as a negative control (9 threads over a count-3 barrier gave 611 early releases and 4662 unclosed cohorts of 20000; 16 over count-5 deadlocked at arrivals 60000, releases 59998) and against the fix (three trigger configurations exact in 43 ms, 40 harness reps clean, 60 consecutive guard runs clean), plus a clang ThreadSanitizer build clean on both the harness and the guard, including a plain non-atomic payload array that only survives if the barrier really establishes the happens-before edge. `tests/anotest_barriercohortguard.c` is registered and green in the 57/57 headless run, and it passes unchanged on Linux against glibc, which is the oracle.

The three Win64 census fixes are inspection-verified against documented API contracts. `filesystem_win64.c:137` needs no hardware check for the fix's shape 〜 one added disjunct on an existing branch, no new API 〜 and reproducing its trigger needs a network redirector or filter driver that returns TRUE with 0 bytes written. `audio_win64.c:589` needs a Windows box that actually falls back to DirectSound (WASAPI refused), buffer loss forced by a focus change under DSSCL_PRIORITY, listening for the garbage burst and confirming writeCursor stays a multiple of blockBytes afterwards. `time_win64.c:148` needs two things: a machine that actually elects TSC (the debug line at :211 reports the election), with a stamp held across a real S3 lid-close and across S4 hibernate, checking the post-resume stamp exceeds the pre-sleep one and that the forward step is the awake interval plus about 0.1%, not the wall-clock suspend duration; and the link surface, since QueryUnbiasedInterruptTimePrecise is exported by KernelBase.dll and documented against Mincore.lib rather than kernel32, so the Windows link line needed mincore added in `src/time/CMakeLists.txt` 〜 landed, and failure there would be a loud unresolved symbol at link, not a silent runtime fault.

The four Windows strays carry their own checks. WASAPI packet-arm latch (round 5): drive a shim vtable that returns AUDCLNT_E_OUT_OF_ORDER from GetBuffer and AUDCLNT_E_INVALID_SIZE from ReleaseBuffer and confirm the render thread stops with exactly one ANO_ERROR naming the HRESULT rather than spinning silently; confirm ordinary underrun and skip traffic never reaches 50 consecutive packet refusals; confirm the padding arm still latches as round 4 landed it, and that the two counters do not sum. DSound recovery: force the DSound fallback, take and return focus with an exclusive-mode app and confirm audio resumes with no permanent silence; inject a Play or Lock refusal after Restore and confirm the 10 ms retry re-enters recovery; and confirm DSBSTATUS_PLAYING is reported immediately after the initial Play on the driver under test, since a driver that lags that bit costs one spurious recovery rather than a hang. WASAPI packet pairing: confirm both init paths still start clean and that the new prefill warning does not appear in a healthy run; confirm the silence prefill still silences the initial buffer; and, the one that actually needs forcing, confirm the zero-frame release is accepted by driving a shim vtable that returns S_OK with a NULL pointer on the Nth GetBuffer and observing that the next GetBuffer succeeds rather than answering 0x88890004. WASAPI terminal latch: unplug a render endpoint mid-playback, stop the audio service, and change the endpoint's shared-mode format, each expecting exactly one ANO_ERROR naming the HRESULT and a device thread that is gone rather than waking at ~100 Hz; a healthy shutdown must emit no error line; and both exit paths should be checked under a COM leak check for exactly one call each to Stop, avRevert, the three Releases, CloseHandle and CoUninitialize, in order.

Whether either Windows invariant gets a Win32-gated guard registered under `if(WIN32)` was raised twice and left open both times, because the campaign's own rule is that a new invariant gets a guard that is seen to fail first, and a target registered from a host that cannot build it would be authored blind. It stays inspection-verified with the checklists above until a Windows runner exists.
