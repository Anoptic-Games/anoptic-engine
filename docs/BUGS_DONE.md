## Removed guards

A second census, taken 2026-07-25 and running the other way. The buckets above ask what defect is missing a check; this section records checks that were deleted for costing without paying.

A guard qualified as frivolous on two conditions together: it rejects inputs that cannot arise under reasonable use of its API, and the effect it prevents is contained 〜 the call merely fails, returns early, or yields a wrong-but-bounded value, with no out-of-bounds access, no UB, no leak, no corruption of unrelated state. Either condition alone acquits. A guard against an absurd input whose effect is a heap overwrite stays, however unreachable the input; a guard on a reachable input stays whatever its effect. Severity scaled with how hot the branch was.

The sweep read roughly 1,650 guard sites across all sixteen modules, one reader per module. Eleven modules came back clean. Thirteen findings in five, plus the `ano_sleep` guard removed the same day and recorded as a `wontfix` in `docs/BUGS.md`. Every removal below is in the tree; the suite was run after and shows the same five pre-existing failures as before, all four of them the open decisions above.

### Why these existed

Four shapes account for all thirteen.

Arithmetic artifacts. Someone traced a wrap or a sentinel and guarded the input that triggers it, without asking whether that input can occur or whether its effect matters. `ano_sleep` (~585 years), `audio_mixer.c:187` (~12.2 million years), `frame.h:94` (71.6 minutes). The tell is platform divergence: `time_linux.c` never carried the `ano_sleep` guard, because splitting `us` into `tv_sec`/`tv_nsec` never forms the product that wraps. A constraint that is real appears in every sibling, or in the header. None of these appear in either.

Invariant distrust. A counter's decrement is guarded against underflow while the matching increment in the same function is not. If the invariant holds neither test is needed; if it does not, the increment is equally wrong. The asymmetry is the argument.

Prototype transliteration. `max(1, ...)` carried across from the Python prototype, where slice semantics gave it meaning. In C it is inert.

Redundant re-checks of a callee's own bound, or of a bound the type already enforces.

### Removed

`src/audio/audio_mixer.c:187` 〜 `if (s->remaining != UINT64_MAX) s->remaining--;`. Guarded the play-until-STOP sentinel against being consumed, which takes 2^64 frames: ~12.2 million years at 48 kHz. Per-sample per-voice in `source_render`, ~3M evaluations/second at 64 voices. The decrement is now unconditional; an unbounded voice counts down from `UINT64_MAX` instead of sitting pinned at it, and the sole reader (`:117`, `remaining == 0 && state == PLAYING`) cannot observe the difference in any real runtime.

`src/audio/dsp/delay.h:54-55` 〜 `if (delay < 1u) delay = 1u; if (delay > d->cap) delay = d->cap;`. Dead at all four call sites, each of which reads a line with the value it was allocated with. The index is masked by `& d->mask` regardless, so a violating delay reads a different in-buffer slot rather than out of bounds. Twelve dead compares per sample on a bus running reverb. The doc comment promised the clamp and was corrected; the file header now says only the fractional read clamps. `ano_dsp_delay_read_frac`'s clamps at `:62-63` were left 〜 they stop a negative or huge float reaching `(uint32_t)delay`, which is UB, so they fail the containment condition.

`src/time/time_win64.c:251` 〜 `if (startTime == 0 || startTime == UINT64_MAX) return -1;` in `ano_busywait`. ## Remediation determinations

A third pass, 2026-07-25, over the notes above. Nine inspections, one agent per finding, each ordered to verify before proposing and then to pick the highest rung of a fix hierarchy that fully neutralizes the defect: structural (reordering makes the bad state unreachable, no added code), type (the bad value becomes unrepresentable), other compile-time (static_assert, signatures), runtime invariant (established once at a seam, inherited everywhere downstream), and guards at the fault site last. Nothing in this section is implemented; it records what should land and why. Of eleven determinations, five land at tier 1, six at tier 4, and zero at tier 5 〜 every check that must exist sits at a seam, none at a fault site. `music_motif.c:472` from the list above was not in scope and stays unverified.

`src/time/` (both notes) 〜 confirmed, tier 1. The sentinel arithmetic is exact: at 10 MHz a failed QPC read comes out of `ano_ticks_to_ns` as `UINT64_MAX - 99`, so every `== UINT64_MAX` check downstream misses the failure it names. Worse, all sentinel producers are unreachable: Microsoft documents QPC/QPF as unable to fail on XP+ (the file targets Win10 1803+ and its own comment at `:40` says so), `mach_absolute_time` is a commpage read, and vDSO `clock_gettime` with a valid constant clockid cannot fail. The kept `== UINT64_MAX` arms recorded under Removed guards at `time_win64.c:257` and `:357` therefore do not deliver what justified keeping them: under the one hypothetical failure mode they were kept for, Win64's busywait hangs identically to Linux and macOS. Determination: delete the sentinel convention from the module entirely 〜 every producer, every check, all three platforms 〜 and make the two one-time init points (`query_perf_freq`, `initialize_timebase`) `abort()` on their impossible branches. The public header never documented a sentinel, so no contract moves; the three `ano_busywait` loops become textually identical; `anotest_time`'s sentinel checks (`:45,52,59`) become vacuous and go in the same sweep, with `testGranularity` as the real dead-clock lock. Bonus defect: `ano_timestamp_ms` returning `UINT32_MAX` as an error collides with a stamp the clock legitimately passes every ~49.7 days.

`log_core.c` `g_batch` 〜 confirmed, tier 4 plus a tier-3 assert. The census already carries it (`docs/BUGS.md:117`, `pending-design-decision`); `anotest_logflood` is this bug, engineered oracles and all. ~164 wide records in one drain pass walk `blen` to the cap, `room = g_batchCap - blen` underflows, and every remaining record writes ~4 KB out of bounds 〜 a multi-MB heap overwrite on the draining thread. Determination: in `drain_and_emit` before each record, if the batch no longer holds one worst-case rendered record (`ANO_LOG_TIME_RESV + ANO_LOG_MSG_MAX + 2`), flush it and reset `blen`; pin `batchCap >= one worst-case record` with a `_Static_assert`. No drops, no truncation, byte-identical output; the only delta is multiple file writes under flood. This settles the open decision above: keep the full-width no-drop contract, pay writes. Flush-per-record (tier 1) was rejected for destroying the batched-drain design on every workload; true-worst-case sizing (tier 3 alone) costs 33.7-134.8 MB.

`music_host.c` motif `n` 〜 confirmed, relocated, tier 4. `expand()` overflows nothing itself; it copies `n` verbatim and the out-of-bounds writes fire downstream in `music_motif.c`'s transforms and realizers (`pitches_at:338`, `ano_motif_invert:186`, `ano_realize_faithful:399`) on the first `ano_music_advance_bar`. `n` is `uint32_t`, so `n = 33` is a one-past stack write and a large `n` runs to gigabytes. Tier 2 fails on arithmetic: `ANO_MOTIF_MAX` is 32 and no integer type's range caps there. Determination: clamp `n` to `ANO_MOTIF_MAX` in `expand()`'s copy loop 〜 the module's established ingress seam, which already degrades out-of-contract `mode`/`cadence` 〜 optionally mirrored in `ano_director_init` for the internal test path. No-op for every input an author can express, so Python parity holds; `ANOPTIC_MUSICGEN.md`'s edit prohibitions do not touch this seam.

`ano_GltfParser.c` 〜 both sub-issues confirmed; validate at tier 4, allocations at tier 1. Verified empirically: a scratch harness ran parse/load_buffers/validate over the three shipped assets (all clean, Sponza's 405 accessors included) and the guard test's fixtures 〜 `cgltf_validate` is exactly the stage that separates them, and `cgltf_accessor_read_*` consults no bound whatsoever without it. `anotest_gltfguard` fails deterministically today; the overrun lands inside a live mimalloc page and `MI_TRACK_ASAN` is off, so no tool in the repo can see it. Determination: one `cgltf_validate` arm after `cgltf_load_buffers`, shaped like the two existing failure arms; then collapse the sixteen unchecked callocs into two sized blocks 〜 one persistent bump block for everything `ModelAsset` owns, one scoped `mi_heap_t` for load-time scratch 〜 which retires fourteen failure points structurally and fixes the arena-rule violation in the same motion. Image-URI path traversal noted as a separate untrusted-input finding.

## Settled open decision (from docs/BUG-HUNT.md)

### log_core.c:817 〜 size-mismatch (bucket 2, anotest_logflood)

The one entry quantity safety did not close, because it is not arithmetic. `g_batch` is sized at ring bytes plus 16 per record on the claim that a record's rendered text fits its ring footprint, but a deferred record renders at its format width, not its stored size, so `"%*d"` width 4000 holds one 64-byte ring line and emits ~4016 batch bytes.

Decide what the logger promises under a wide-format flood. Bounding rendered width at capture (reject or clamp a format whose width exceeds the record's share) keeps the drain's memory profile flat and changes what the public logger accepts. Sizing the batch by a rendered bound with checked per-record copies keeps the contract and lets the drain allocate against a hostile format string. The first is a contract change, the second is a memory-profile change; the checked `room` subtraction is required either way and is not by itself the fix.

Settled 2026-07-25 by a third answer neither horn anticipated: the contract stands 〜 full width, no drops 〜 and the memory profile stays flat; the drain flushes mid-pass whenever less than one worst-case rendered record of room remains, so a flood pays file writes, not memory and not contract. anotest_logflood is green and the census entry is closed. Details under "Remediation determinations".
